# QMIK — тестовая сборка для Render (причина обращения)

Это обновление пользовательской сборки на **Node.js + Express + EJS + SQLite**, без изменения остальных рабочих сценариев.

## Что изменилось

На странице **«Талоны»** после колонки **«Статус»** появилась **«Причина обращения»**; кнопка **«Перевести на актив» / «Вернуть статус»** теперь расположена в следующей колонке **«Действие»**.

- Штатный сотрудник (`staff`) и администратор (`admin`) выбирают причину из одного выпадающего списка с четырьмя группами.
- По мере ввода список сразу фильтруется. Можно выбрать мышью, стрелками и `Enter`; `Esc` отменяет ввод, «Очистить» сбрасывает выбор.
- Хелпер (`helper`) видит выбранную причину, но не может её менять.
- Изменения сохраняются в SQLite сразу при выборе и показываются другим открытым страницам через SSE (без F5).
- Поле необязательное; никаких новых требований для перевода талона на актив не добавлено.
- На существующей базе колонка `reason` добавится автоматически при запуске, старые талоны и пользователи сохранятся.

### Варианты

**СМЗ:** РФ СМЗ, РФ СМЗ 16+, РФ СМЗ ГЛУХ, ОА СМЗ.

**ГПХ:** РФ ГПХ, ОА ГПХ ПН1.

**Переходы:** ГПХ->СМЗ, ЛАВКА->ЕДА, ЕДА->ЛАВКА.

**Другое:** ОФФ.

Перечень хранится в `data/reasons.json`; backend проверяет значение по нему, поэтому произвольную причину сохранить нельзя.

## Обновление тестового проекта на Render

1. Скопируй **содержимое архива** в корень своего GitHub-репозитория поверх старых файлов.
2. Сохрани свой `.env` локально и **не загружай его в GitHub**. В этом архиве реальных секретов нет. Переменные Render сохраняются в панели Render.
3. Выполни:

```bash
git add .
git commit -m "Add reason autocomplete"
git push
```

Render сделает деплой автоматически, если включён Auto Deploy. `render.yaml` и Node 22 оставлены как в исходной сборке.

## Локальный запуск

```bash
cp .env.example .env
# Измени SESSION_SECRET, HELPER_PASSWORD, STAFF_PASSWORD в .env
npm install
npm start
```

Открой `http://localhost:3000`.

> Для тестовой SQLite-базы на бесплатном Render действуют прежние ограничения: она может исчезнуть при рестарте/новом деплое. Для реальных персональных данных нужна постоянная база и HTTPS.
