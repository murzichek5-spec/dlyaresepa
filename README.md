# Простая офисная система талонов

Стек специально простой:

- Node.js 22
- Express
- EJS
- обычный CSS
- SQLite
- обычные SQL-запросы без ORM
- SSE для live-обновлений без Socket.IO

## Текущая логика

1. Helper входит в систему.
2. На странице «Создать талон» вводит только ФИО и телефон.
3. Работа с уже созданными талонами находится на отдельной странице «Талоны».
4. В общем списке Helper у своих талонов может отмечать Telegram, Мой налог и Яндекс Про.
5. Каждая галочка сразу сохраняется в SQLite, а Staff видит изменение в реальном времени без F5.
6. Staff присваивает или исправляет номер талона в колонке «№ талона». Helper видит номер в реальном времени.
7. Helper у своего талона меняет готовность: «Не готов» (красный) ↔ «Готов» (зелёный). Staff видит это в реальном времени.
8. Staff переводит талон в статус «Переведен на актив». Для этого сначала должен быть присвоен номер талона.
9. Если Staff случайно перевёл талон в актив, кнопка «Вернуть статус» возвращает последнее состояние Helper: «Готов» или «Не готов».
10. Статуса «Ожидает» в интерфейсе больше нет.
11. Helper может удалить созданный им талон. Staff может удалить любой талон. Перед удалением браузер просит подтверждение.
12. Создание, сервисы, номер, готовность, перевод в актив и удаление синхронизируются через SSE.

## Запуск локально

```bash
npm install
cp .env.example .env
npm start
```

На Windows вместо `cp`:

```bat
copy .env.example .env
```

Открыть:

```text
http://localhost:3000
```

Перед реальным использованием поменяй `SESSION_SECRET`, `HELPER_PASSWORD` и `STAFF_PASSWORD`.

## База

SQLite создаётся автоматически:

```text
db/office.db
```

SQL-схема:

```text
db/schema.sql
```

Талоны автоматически удаляются каждый день в 00:00. Пользователи и пароли не удаляются. Если сервер был выключен в полночь, старые талоны будут удалены при следующем запуске.

## Render

В `render.yaml` закреплён Node.js 22.22.0.

Для теста можно использовать Free Web Service. Без Persistent Disk локальный файл SQLite на Render может пропасть при redeploy/restart. Для постоянной рабочей базы нужен Persistent Disk или отдельная серверная SQL-база.
