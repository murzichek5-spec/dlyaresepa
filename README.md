# QMIK — общие комментарии для твоей сборки

Основа: загруженная сборка «поебота работа(3).zip»; изменены только файлы, нужные для комментариев.

## Что добавлено

- «Комментарий» у каждого талона в трёх разделах: **Талоны**, **Очередь**, **Обработанные талоны**.
- Все три отдела могут читать, дописывать, заменять или очищать комментарий на доступном этапе талона; после завершения комментарий остаётся редактируемым в «Обработанных талонах».
- Автоматическое сохранение по кнопке «Сохранить», до 1000 символов, синхронизация через SSE.
- Проверка версии на сервере: комментарий нельзя молча перезаписать более старой копией.
- Миграция таблицы `tickets` происходит автоматически и не удаляет существующие талоны.

## Запуск и обновление на Render

1. Скопируй **содержимое** этой папки в корень GitHub-репозитория проекта.
2. Не удаляй и не переименовывай Environment Variables в Render.
3. Выполни `git add . && git commit -m "Add shared ticket comments" && git push origin main`.
4. Render должен автоматически обновить сервис, если Auto Deploy включён.

В ZIP **нет** секретного `.env`, файла базы SQLite или каталога `.git`. Эти файлы остались только в твоей локальной копии. Проверь `.gitignore` перед отправкой в GitHub.

**Примечание:** при одновременном редактировании текста разными людьми последний отправивший устаревшую версию получит ошибку и должен будет открыть комментарий заново.


## v22 — персональная цветовая плашка специалиста

На странице **Очередь → Мой профиль** специалист активации может изменить:
- отображаемое имя (логин для входа не меняется);
- цвет фона плашки «У <имя>»;
- цвет текста плашки.

На странице профиля есть живой предпросмотр. Настройки сохраняются по кнопке **«Сохранить профиль»**, хранятся в SQLite в таблице `users` и не сбрасываются при обычных перезапусках приложения, если сохранён сам файл SQLite. На странице очереди все уже закреплённые талоны обновляются через SSE сразу после сохранения цветов. Свободные талоны отображаются в прежнем стиле.

При запуске существующая SQLite база автоматически получит поля `owner_bg_color` и `owner_text_color`; новые переменные окружения не нужны. Рекомендуются контрастные сочетания цветов, иначе текст может быть трудно читать. Важно: на бесплатном Render файл SQLite может потеряться после рестарта или деплоя, как и другие локальные данные.
